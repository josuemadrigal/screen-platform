# Deploying Screen Platform

The server runs prebuilt Docker images. Nothing is built there: no source code, no Node,
no GitHub access. You build the images on your workstation, push them to GitHub Container
Registry, and the server pulls them.

```
workstation ── build-and-push.sh ──> ghcr.io ──> server: docker compose pull && up -d

Internet ──443──> Caddy (web image) ──┬── panel.DOMAIN  (static admin panel)
                                      ├── tv.DOMAIN     (static TV client)
                                      └── api.DOMAIN ──> api image ──> postgres
```

The frontends read the API URL at runtime (`/config.js`, generated by Caddy from `DOMAIN`),
so the same images work for any domain.

## 1. Publish the images (on your workstation)

Once, log in to the registry with a GitHub token that has the `write:packages` scope:

```bash
docker login ghcr.io -u josuemadrigal
```

Then, every time you want to release:

```bash
deploy/build-and-push.sh            # pushes :latest
deploy/build-and-push.sh v1.0.0     # pushes :v1.0.0 and :latest
```

Images are built for `linux/amd64` (the server), even from an Apple Silicon Mac.

The packages are private by default. Either make them public on GitHub (Packages → package →
Package settings → Change visibility) or, on the server, `docker login ghcr.io` with a token
that has `read:packages`.

## 2. Server

- Ubuntu 22.04/24.04, Docker Engine + Compose v2 (`curl -fsSL https://get.docker.com | sh`).
- Ports 80 and 443 reachable from the Internet (open in the firewall / forwarded by the router).
- DNS: `A` (or `CNAME`) records for `panel.DOMAIN`, `tv.DOMAIN` and `api.DOMAIN` pointing to the
  server's public IP. Let's Encrypt validates them over port 80, so DNS must be live before
  the first start.

Only two files are needed on the server: `docker-compose.server.yml` and `.env`.

```bash
mkdir -p /opt/screen-platform/storage && cd /opt/screen-platform
curl -fsSLO https://raw.githubusercontent.com/josuemadrigal/screen-platform/main/deploy/docker-compose.server.yml
curl -fsSL  https://raw.githubusercontent.com/josuemadrigal/screen-platform/main/deploy/.env.example -o .env
mv docker-compose.server.yml docker-compose.yml
nano .env      # DOMAIN, ACME_EMAIL, POSTGRES_PASSWORD, JWT_SECRET (openssl rand -base64 48), STORAGE_PATH
```

If the repository is private those `curl` calls need a token; copying the two files over
`scp` works just as well.

Start:

```bash
docker compose pull && docker compose up -d && docker compose logs -f --tail 50
```

The API applies database migrations on start. Caddy requests the certificates on the first
HTTPS hit; give it a minute. Then:

1. `https://api.DOMAIN/health` → `{"status":"ok"}`.
2. Create the first admin (only works while the users table is empty):
   ```bash
   curl -X POST https://api.DOMAIN/auth/register -H 'Content-Type: application/json' \
     -d '{"name":"Admin","user":"admin","email":"you@example.com","password":"a-strong-password"}'
   ```
3. Log in at `https://panel.DOMAIN`, create a screen, upload a video, build a playlist.
4. On each TV open `https://tv.DOMAIN` (or install the Android app) and enter the screen code.

## 3. Updating

Workstation: `deploy/build-and-push.sh`. Server:

```bash
cd /opt/screen-platform && docker compose pull && docker compose up -d
```

To pin a version instead of `latest`, set `IMAGE_TAG=v1.0.0` in the server's `.env`.

## Backups

Two things hold state: the database volume and the `storage/` folder with the videos.

```bash
docker compose exec postgres pg_dump -U screen_user screen_db | gzip > backup-$(date +%F).sql.gz
tar czf storage-$(date +%F).tar.gz storage/
```

## Android TV app

The APK is the one artifact that still needs the API URL at build time. In
`screen-tv-client/.env` set `VITE_API_URL=https://api.DOMAIN` and `VITE_SOCKET_URL=https://api.DOMAIN`,
then follow `screen-tv-client/BUILD.md`. Because the API is served over HTTPS, no cleartext
exception is needed.

## Alternatives

- **Build on the server instead of pulling images**: clone the repository on the server and use
  `docker-compose.prod.yml` with `--build`. Same layout, needs source access and more RAM.
- **Nginx instead of Caddy**: `nginx/screen-platform.conf` has the three server blocks (SPA
  fallback, WebSocket upgrade headers, 1 GB upload limit) ready for `certbot --nginx`. Publish
  the API on `127.0.0.1:4006`, build the frontends with `VITE_API_URL` set, and copy the `dist/`
  folders to `/var/www/screen-platform/{panel,tv}`.
